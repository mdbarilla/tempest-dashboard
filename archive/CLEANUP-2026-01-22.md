## Critical Fix Applied

### Nginx Path Configuration
**Problem**: nginx was pointing to wrong directory, causing deployments to show old version

**Before**:
```nginx
root /home/mbarilla/tempest/apps/dashboard/build;
```

**After**:
```nginx
root /home/mbarilla/deployment/dashboard;
```

This fix is now **prominently documented** in DEPLOYMENT.md with warnings and troubleshooting steps.

## Future Maintenance Guidelines

### For New Features
1. Update `CHANGELOG.md` with version and changes
2. Update `README.md` if major features added
3. No need for separate implementation docs

### For Deployments
1. Run `./scripts/build-and-deploy.sh`
2. Follow `DEPLOYMENT.md` steps
3. Old builds automatically go to `build-output/`
4. Periodically clean old `.tar.gz` files

### For Documentation
- **Don't create**: DEPLOY-v1.3.6.md, QUICKSTART-NEW.md, etc.
- **Do update**: DEPLOYMENT.md and CHANGELOG.md
- **Archive if needed**: Move to `archive/old-docs/` rather than delete

## Benefits

1. **Faster onboarding**: New developers see clear README and single deployment guide
2. **Less confusion**: No conflicting documentation
3. **Easier maintenance**: Update one file, not five
4. **Cleaner workspace**: Root directory is uncluttered
5. **Preserved history**: Nothing lost, just organized

## What to Do Next Time

When deploying a new version:

1. Build: `./scripts/build-and-deploy.sh`
2. Update: `CHANGELOG.md` with changes
3. Deploy: Follow `DEPLOYMENT.md`
4. Clean: `rm ~/tempest-v1.3.4*.tar.gz` (old builds)

**Do NOT create**:
- ❌ DEPLOY-v1.3.6-NOTES.md
- ❌ QUICKSTART-v1.3.6.md
- ❌ NEW-FEATURES.md

**Do update**:
- ✅ CHANGELOG.md
- ✅ DEPLOYMENT.md (if process changes)
- ✅ README.md (if major features)
